# Changelog

All notable changes to the ambulance tracking system are recorded here. The project is still pre-1.0; entries are grouped by capability rather than semantic-version releases until the first production release is cut.

## Unreleased

### Dispatcher and user experience
- Reworked the dispatcher into a map-first operations surface inspired by familiar navigation applications: floating search, fleet drawer, selected-unit bottom sheet, map tools, and responsive mobile behavior.
- Added smooth live-marker interpolation, selected-unit pulse animation, sliding fleet/admin sheets, alert transitions, and reduced-motion support.
- Added vehicle search, real fleet freshness states, live telemetry summaries, and route playback controls directly over the map.
- Added map-click ETA targets with road-routing support when an OSRM-compatible router is configured and a clearly labeled kinematic fallback otherwise.
- Added a dispatcher crash-alert banner with locate and acknowledge actions.
- Added an administration sheet for one-time ambulance enrollment, device revocation, scoped AI tokens, and TOTP MFA setup.

### Device enrollment
- Added short-lived, one-time enrollment codes generated by an administrator.
- Added `POST /api/v1/device/enroll` so a new Android tracker can exchange a one-time code for its long-lived per-device credential.
- The Android app now has a built-in HTTPS server endpoint and normally asks only for the one-time enrollment code.
- Server URL, vehicle code, and device key remain available under **Advanced settings** for development/recovery instead of being part of routine setup.
- Existing device credentials remain encrypted with Android Keystore.
- Revoking a device immediately revokes its server sessions.

### Authentication and security
- Added optional TOTP MFA for dispatcher/admin accounts.
- TOTP seeds are encrypted at rest using AES-256-GCM with a deployment-level key supplied through `MFA_ENCRYPTION_KEY`.
- Added short-lived, one-use MFA login challenges rather than issuing an authenticated browser session after password verification alone.
- Added stronger browser security headers and `Cache-Control: no-store` on API responses.
- Added explicit role enforcement on administrative endpoints.
- Added hashed, scoped, revocable API tokens for read-only machine/AI access.
- Continued to keep database and application services off public host ports in the production topology.

### Crash detection and operational events
- Added advisory Android crash-candidate detection using linear acceleration where available, accelerometer fallback otherwise, a speed gate, g-force threshold, and cooldown.
- Crash candidates are explicitly **not** treated as confirmed crashes; dispatcher verification is required.
- Added enqueue-before-send persistence for crash alerts so an event detected without connectivity is retried later.
- Added persisted vehicle events, dispatcher realtime broadcasts, event history, and acknowledgement endpoints.

### AI integration
- Added scoped read-only AI context endpoints:
  - `GET /api/v1/ai/fleet-context`
  - `GET /api/v1/ai/vehicles/{vehicleID}/context`
- AI context provides normalized operational telemetry, freshness, route summaries, and unacknowledged operational events without exposing device credentials or administrative actions.
- AI tokens are generated once, stored only as hashes, scoped, expirable, auditable, and revocable.
- No model provider is embedded in the tracking server; local or external assistants can consume the same controlled read API.

### Network and performance
- Added gzip compression for offline replay batches; repetitive JSON telemetry compresses efficiently without introducing a new binary protocol dependency.
- Increased replay batches to 400 records and changed Android backlog draining from recursive calls to an iterative loop.
- Added compressed and decompressed request-size limits to protect the replay endpoint against oversized payloads and decompression bombs.
- Kept live WebSocket telemetry uncompressed because individual frames are small and compression would add CPU/state overhead for little bandwidth benefit.
- Added a short-lived in-process ETA cache.
- Added an index supporting device/session/sequence replay lookups.
- Redis remains intentionally absent in the single-API-node architecture; see `docs/PERFORMANCE.md` for the scale-out threshold where Redis/NATS becomes useful.

### Validation
- Added integration coverage for encrypted TOTP generation/verification, one-time enrollment, gzip replay, crash-event ingestion, and scoped AI context.

## Production hardening

### Reliability and operations
- Added safe PostgreSQL custom-format backup tooling with readiness checks, SHA-256 checksums, atomic publish, permissions, and retention.
- Added an isolated restore drill that restores into a disposable database and verifies core tables without overwriting production.
- Added deployment health checks for the database, API edge path, web application, Caddy, and Cloudflare connector.
- Bounded Docker JSON logs to avoid silent disk exhaustion.
- Added safe dispatcher-password and device-key rotation tooling with session revocation.
- Added stable Android release-signing support and a manual signed-APK GitHub Actions workflow.

### Testing
- Added PostGIS-backed integration coverage for two simultaneous ambulance tracker WebSockets.
- Verified independent fleet state and dispatcher broadcasts between vehicles.
- Added regression coverage proving historical playback uses the newest tracking session and cannot join an old simulated route to a real route.
- Added password-rotation tests proving old passwords and old sessions stop working.
- Production-hardening CI passed backend, web, Android, and deployment-config lanes.

## First physical-device validation
- Proved Android GNSS acquisition through the public Cloudflare edge into the Go API and PostgreSQL/PostGIS.
- Proved live dispatcher WebSocket updates from a physical tracker.
- Proved offline collection/replay across an extended period without network connectivity.
- Recorded and reconstructed a real multi-kilometre route from persisted telemetry.
- Observed stationary GNSS wander and fixed it with GPS preference, accuracy bounds, stationary dead-band/heartbeat behavior, and implausible-jump rejection.
- Observed historical test-session contamination and fixed playback to isolate the newest `tracking_session_id`.

## Dispatcher map and playback
- Replaced the initial basic dashboard with MapLibre-based fleet operations UI.
- Added all provisioned ambulance markers, live presence, telemetry detail, and freshness states.
- Added 1-hour, 6-hour, and 24-hour route playback with bounded server-side sampling.
- Added explicit tracker connected/disconnected WebSocket presence events.
- Removed fake incidents, fake analytics, decorative operational data, gradient-heavy styling, and generated-looking branding.

## Android tracker usability
- Added a live MapLibre position map and local route trail.
- Fixed map gestures inside the scroll container.
- Stopped GPS updates from fighting manual pan/zoom and added an explicit recenter action.
- Added Android system-bar inset handling.
- Added CI upload of the debug APK for remote installation/testing.

## Initial system foundation
- Added Go HTTP/WebSocket API, PostgreSQL/PostGIS schema, dispatcher authentication, tracker authentication, audit logging, and health checks.
- Added native Android/Kotlin foreground GNSS tracking.
- Added SQLite enqueue-before-send offline queue and idempotent replay using `(device_id, tracking_session_id, sequence_number)` uniqueness.
- Added React/TypeScript dispatcher application.
- Added Caddy reverse proxy and Cloudflare Tunnel deployment with no public origin IP requirement.
- Established `feature/fix/docs -> dev -> main` pull-request workflow.
